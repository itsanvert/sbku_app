# Deployment Guide for Render.com

This project is configured for easy deployment on [Render.com](https://render.com) using Docker.

## Prerequisites
1. A GitHub repository with your code pushed.
2. A Render.com account.

## Step 1: Prepare Firebase Credentials
1. In your Firebase Console, go to **Project Settings > Service Accounts**.
2. Click **Generate New Private Key** and download the JSON file.
3. You will need the content of this file for the Render "Secret File".

## Step 2: Deploy to Render
1. Log in to [Render.com](https://render.com).
2. Click **New +** and select **Blueprint**.
3. Connect your GitHub repository.
4. Render will automatically detect the `render.yaml` file and set up:
   - **Web Service**: `sbku-backend` (using Docker).
   - **PostgreSQL Database**: `sbku-db` (Free tier).
5. Before clicking "Apply":
   - **Secret Files**: Add a secret file named `firebase-credentials.json` and paste the contents of your Firebase JSON key.
6. Click **Apply**.

## Step 3: Initial Data Migration (One-time)
Once the backend is live, you need to migrate your existing data to Firestore:
1. Go to your Web Service on Render.
2. Click on the **Shell** tab.
3. Run the following command:
   ```bash
   php artisan firestore:migrate
   ```

## Step 4: Update Mobile App
1. Get your backend URL from Render (e.g., `https://sbku-backend.onrender.com`).
2. Update the `API_URL` in `frontend/.env`:
   ```env
   API_URL=https://sbku-backend.onrender.com
   ```
3. Rebuild/Restart your Flutter app.

## Environment Variables
The `render.yaml` handles most variables. If you need to add custom ones:
- Go to **Environment** settings in the Render dashboard.
- Add your keys (e.g., `APP_KEY`, `FIREBASE_PROJECT_ID`, etc.).
- Note: `APP_KEY` is automatically generated by the Blueprint if not provided.

## Database Note
This deployment uses Render's **Free PostgreSQL**. Note that Render's free databases expire after 90 days. For long-term use, consider a paid plan or an external database provider.
Since you are using Firestore as your primary real-time data store, ensure your models use the `SyncsToFirestore` trait to keep them in sync.
